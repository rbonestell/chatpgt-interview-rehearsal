# Practice that produces observable improvement

Load for requested retries, drills, short rehearsals, or follow-up rounds. Reuse verified inputs. Do not rerun full intake for the same role.

## Retry loop

Preserve the selected feedback timing. During an end-only interview, a plain "retry" requests another attempt, not coaching. Re-ask the same question neutrally, wait, and retain both attempts without increasing the main-question count. Defer improvement targets, hints, scores, and comparisons to the debrief. Do not label an unassisted retry as coached simply because it is a second attempt.

For per-answer feedback, post-debrief practice, or an explicit request for coaching:

1. Choose one priority from actual answer evidence.
2. State the concrete target in one sentence, such as explaining the individual's decision and a verified outcome.
3. Re-ask the question and wait. Give hints only when requested or consistent with the selected coaching mode.
4. Compare the revised answer with the original against the same criterion. Name what improved and what still needs work.
5. If useful, offer a different question testing the same competency to distinguish learning from memorizing a script. Count an accepted new question separately; it is not another attempt at the original question.

Explicit coaching during an end-only interview pauses the simulation and marks the resulting attempt as assisted. Offer to resume or retry afterward; retain end-only feedback for subsequent interview questions unless the user changes it.

Never manufacture score improvement. Track unaided, hinted, and coached attempts separately. End the drill when the target is met or the user wants to move on; do not create an endless exercise.

## Focused options

- Concise introduction: practice a short role-relevant narrative, then remove unrelated detail.
- Behavioral story: choose an actual experience; strengthen action and result without invented metrics. Use bullets rather than a script to memorize.
- Gap explanation: acknowledge the real limit, connect transferable evidence, and state a credible learning approach.
- Technical or case reasoning: clarify assumptions, work through an approach, explain tradeoffs, and propose verification.
- Candidate questions: practice a useful question and a natural follow-up, keeping unknown company answers clearly hypothetical.

A user who only wants a generic drill may proceed without a full resume or posting; label it generic or limited-context. For targeted practice, reuse the target materials or ask only for the smallest missing context. A five-minute request can become two main questions and a short debrief; do not promise timing you cannot measure.

## Optional take-away and continuity

After the debrief, offer a concise preparation brief only if it would help: target role, supported strengths, three to five real story cues, gaps and honest responses, practice priorities, and questions to ask. Do not auto-create documents or ask another setup questionnaire. If a file is requested, use available file creation and saving tools and verify success before linking it.

On a request to resume later or move chats, provide a user-visible checkpoint: source coverage, role, settings, completed question identifiers, concise answer evidence, assistance status, pending question, and next exercise. Omit unnecessary personal details; do not promise durable memory or cross-chat access to attachments. A request to forget an input means stop using it; do not claim that host-stored files or logs were deleted unless an authorized deletion tool actually confirms it.
